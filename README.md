# AI-чат з MCP-серверами

Веб-чат на Next.js, у якому AI-помічник відповідає на запитання, користуючись
публічними MCP-серверами: завантаження сторінок, свіжа документація бібліотек,
покрокове мислення, GitHub, Playwright і читання файлів у тестовій папці.

**Стек:** Next.js 16 (App Router) · TypeScript (strict) · Tailwind CSS 4 ·
Vercel AI SDK 7 (`ai`, `@ai-sdk/react`, `@ai-sdk/mcp`) · Vitest

## Можливості

- Стримінг відповіді в реальному часі (`streamText` → `useChat`)
- Markdown-рендеринг відповідей (таблиці, списки, код-блоки — react-markdown + GFM)
- Згортуваний блок «Міркування» (reasoning parts): працює з gpt-oss на Groq
  (`reasoningFormat: "parsed"`); у OpenAI summaries доступні лише верифікованим
  організаціям — тоді блок зʼявиться й там
- Видно кожен виклик інструмента: сервер, назва, параметри, результат —
  блок розгортається/згортається
- Панель статусу MCP-серверів: підключено / помилка / вимкнено, перелік
  інструментів, перемикач on/off для кожного сервера
- Якщо сервер недоступний — чат не падає: сервер виключається з інструментів,
  а причина помилки видна в панелі
- Перемикач LLM-провайдера: Gemini (безкоштовний tier) / Groq (безкоштовний) /
  Claude / OpenAI — недоступні без ключа опції сірі
- Історія діалогів у localStorage (створення, перемикання, видалення)
- Адаптивна верстка: на мобільному історія та MCP-панель — висувні drawer'и
- Новий MCP-сервер додається через `mcp.config.json` без зміни коду

## Запуск

Вимоги: Node.js 22+, `uv`/`uvx` ([встановлення](https://docs.astral.sh/uv/getting-started/installation/)) —
потрібен для Fetch MCP (офіційний сервер — Python-only).

```bash
cp .env.example .env.local   # і вписати ключі
npm install
npm run dev                  # http://localhost:3000
```

Мінімум один ключ LLM-провайдера обовʼязковий. Безкоштовні варіанти:

| Провайдер | Ключ | Де взяти |
|---|---|---|
| Gemini | `GOOGLE_GENERATIVE_AI_API_KEY` | [aistudio.google.com](https://aistudio.google.com) — безкоштовно, без картки (увага: free tier має малі денні квоти) |
| Groq | `GROQ_API_KEY` | [console.groq.com](https://console.groq.com) — безкоштовно, без картки |

Для GitHub MCP потрібен `GITHUB_TOKEN` — fine-grained PAT з read-only доступом
(repo metadata / issues / PRs). Без нього сервер покаже помилку 401 у панелі,
решта чату працює. `CONTEXT7_API_KEY` опціональний (без нього — нижчі ліміти).

### Тести

```bash
npm test          # vitest: конфіг, env-інтерполяція, MCP-менеджер (з моками)
npm run test:e2e  # playwright: чат-флоу з замоканими API (стримінг, tool-блоки,
                  # історія, перемикачі серверів) — не потребує ключів
```

### Docker

```bash
docker compose up --build    # читає ключі з .env.local
```

Образ містить `uv` (Fetch MCP) і попередньо завантажені npx-пакети MCP-серверів.
Деплой на Vercel **не підтримує stdio-сервери** (uvx/npx child processes) —
тому «чесний» деплой це Docker; у serverless-оточенні працювали б лише
HTTP-сервери (Context7, GitHub).

## Конфігурація MCP-серверів

`mcp.config.json` — список серверів, кожен:

```jsonc
{
  "id": "github",                 // унікальний kebab-case id
  "name": "GitHub",
  "description": "…",             // показується в панелі
  "enabled": true,                // стартовий стан (перемикається в UI)
  "transport": {
    "type": "http",               // "http" | "sse" | "stdio"
    "url": "https://api.githubcopilot.com/mcp/",
    "headers": { "Authorization": "Bearer ${GITHUB_TOKEN}" }
  },
  "allowedTools": ["…"]           // опціонально: whitelist інструментів
}
```

- `${VAR}` підставляється з env на сервері; ключі в конфіг не потрапляють.
  Якщо змінної нема — header просто відкидається (опціональна автентифікація).
- `allowedTools` використано для read-only Filesystem MCP: офіційний сервер
  не має `--readonly`, тож записуючі інструменти просто не експонуються моделі.
- Інструменти в моделі іменуються `<serverId>__<tool>`, щоб уникнути колізій
  і атрибуції виклику до сервера в UI.
- Для GitHub whitelist лишає 12 read-only інструментів із 46 — менший контекст
  і жодних write-операцій.
- Для Playwright whitelist лишає 11 браузінг-інструментів із 25 — зокрема
  відрізані `browser_evaluate`/`browser_run_code_unsafe` (виконання довільного
  JS), бо чат читає недовірені сторінки і вразливий до prompt-injection.
- Великі результати інструментів (пошук issues, сторінки) обрізаються на
  сервері до 6K символів — захист контекст-вікна і TPM-лімітів безкоштовних
  tier'ів (у Groq це 8K токенів/хв).

Щоб додати новий сервер — додай обʼєкт у масив і перезапусти dev-сервер. Код
змінювати не треба.

## Приклади запитів (по одному на кожен MCP)

1. **Fetch:** «Що написано на сторінці https://nextjs.org/blog?»
2. **Context7:** «Як у Next.js 16 працює revalidateTag? Подивись у свіжій документації.»
3. **Sequential Thinking:** «Розбий на кроки: як мігрувати великий застосунок з Pages Router на App Router?»
4. **GitHub:** «Знайди в репозиторії vercel/ai відкриті issues про MCP»
5. **Filesystem:** «Які файли лежать у папці sandbox і що в них?»
6. **Playwright** (вимкнений за замовчуванням — увімкни в панелі): «Відкрий example.com і скажи, який там заголовок»

## Архітектура

```
mcp.config.json ─► lib/mcp/config.ts (zod + ${ENV} інтерполяція)
                      │
                      ▼
               lib/mcp/manager.ts ── singleton, статуси, таймаути,
                      │               graceful degradation, toggle
          ┌───────────┼───────────────┐
          ▼           ▼               ▼
  api/chat (streamText + tools)  api/mcp (GET статуси / PATCH toggle)
          │
          ▼
  useChat → message.parts → текст + dynamic-tool блоки (розгортаються)
```

## Що встигли / не встигли, час, AI-інструменти

**Встигли:** все з обовʼязкового скоупу + всі «буде плюсом»: юніт-тести
(Vitest, 19) **і** e2e-тести (Playwright, 4 — чат-флоу, tool-блоки, історія,
перемикачі MCP; герметичні, API замокані у wire-форматі AI SDK, ключі не
потрібні), історія діалогів, конфіг без коду, Docker. Понад план: 4-й провайдер
(Groq), markdown-рендеринг, reasoning-блок, UX-поліш (автоскрол, копіювання,
regenerate, перейменування чатів).

**Не встигли / компроміси:**
- стан перемикачів серверів живе в памʼяті процесу (скидається при рестарті) —
  персист у файл/БД був би наступним кроком;
- Playwright MCP вимкнений за замовчуванням (повільний старт браузера) —
  вмикається тоглом у панелі, працює з локальним Chrome; у Docker-образі
  браузера нема (економія ~400MB — задокументований компроміс);
- безкоштовні tier'и тісні: Gemini 3.8-flash — 20 запитів/день, Groq — 8K
  токенів/хв (multi-step ланцюги з багатьма серверами можуть упиратись у ліміт —
  зайві сервери можна вимкнути в панелі).

**Час:** ~5 годин на обовʼязковий скоуп і бонуси; ще ~2 години на понадпланове
(e2e, markdown, reasoning, UX) — разом ~7 годин.

**AI-інструменти:** проєкт зроблено в парі з Claude Code (Anthropic): ресерч
актуальних версій AI SDK 7 / MCP-екосистеми з верифікацією по npm/GitHub,
генерація коду, дебаг (зокрема діагностика 503/квот Gemini free tier),
тести. Архітектурні рішення і код-рев'ю — людина.
